# こもれび — L-system botanical studio

リアルな樹木の形を、気軽に試してモデリングするローカルWebアプリです。日本語UI、3Dプレビュー、成長タイムライン、保存、PNG / GLB / JSON書き出しを備えています。

計算はRustバックエンド、表示はTypeScript + Three.jsです。L-systemの展開・枝の座標計算はブラウザーのメインスレッドでは実行しません。クロマツはパラメトリックL-systemから連続した曲面の枝と立体的な針葉を生成し、針葉の房をインスタンシングします。各樹種の枝も連続した曲面として生成します。

クロマツを選択すると、樹冠の広がり・枝の曲がり・針葉密度・針葉長を調整できます。シラカバ・モミジ・サクラ・シダにも樹種別の形状と立体的な葉・花を用意しています。ナラ・シダレヤナギ・トウヒ・イチョウを加え、シダを含む全9種類に対応しています。0〜16世代で、既存の枝の位置を保ちながら枝ごとの発芽・伸長・肥大が進みます。タイムラインに処理時間の概算を表示します。[生成方式と操作](docs/pine-model.md)、[参考写真とテクスチャの出典](docs/tree-references.md)も参照してください。

## セットアップと起動

### Dockerで起動（推奨）

Docker Desktop（Windows / macOS / Linux）またはDocker EngineとComposeを用意し、起動してください。ホスト側のRust・Node.js・Cコンパイラーは不要です。WindowsではLinuxコンテナーを使用します。

リポジトリ直下で実行します。

```sh
docker compose up --build -d
```

[http://127.0.0.1:5173](http://127.0.0.1:5173) を開きます。初回はイメージ取得とコンパイルに数分かかります。

```sh
docker compose ps          # 起動・health状態
docker compose logs -f     # ログ（Ctrl+Cでログ表示終了）
docker compose down        # 停止
```

変更の反映は再度 `docker compose up --build -d`。ポートを変更する場合はリポジトリ直下の `.env` に `APP_PORT=5174` などを設定してください。ホストへの公開は127.0.0.1限定です。ネイティブ版が5173で起動中なら先にCtrl+Cで停止してください。保存データはSQLiteに保管し、名前付きボリューム `komorebi-data` で再ビルド・再起動後も保持します。`docker compose down -v` は保存データも削除するため、通常の停止では `-v` を付けないでください。

[Dockerのマルチステージビルド](https://docs.docker.com/build/building/multi-stage/)でRustとWebをコンテナー内でコンパイルし、実行用イメージには実行ファイルとWeb配信物だけを含めます。Linux amd64 / arm64向けのベースイメージを利用し、使用するマシンのアーキテクチャでビルドします。

### Tailscaleからアクセス

ホストと接続端末を同じtailnetへ接続します。`tailscale ip -4` でホストのIPを確認し、ルートの `.env` に `TAILSCALE_IP=100.x.x.x` を設定してください。

```sh
docker compose -f compose.yaml -f compose.tailscale.yaml up -d --wait
```

接続端末で `http://<TAILSCALE_IP>:5173` を開きます（APP_PORTを変えた場合はその番号）。localhostと指定したTailscale IPにだけ公開します。Docker Desktopを使用し、既定コンテキストで接続できない場合は `docker --context desktop-linux compose` を使用してください。ホストのDockerとTailscaleが稼働している必要があります。

更新時も両方のComposeファイルを指定して `up --build -d` を実行してください。Tailscale公開をやめる場合は通常の `docker compose up -d` でlocalhost限定へ戻せます。tailnetのアクセス制御も適用されます。同じサーバーのライブラリと作業中データはlocalhost/Tailscale間で共有されます。旧ブラウザー保存は、そのデータを保存したURLのマイライブラリで「旧ブラウザー保存を取り込む」を押してください。

### ネイティブで起動

Node.js 24以上と[公式Rustツールチェーン](https://rust-lang.org/tools/install/)をインストールしてください。WindowsではRustの案内に従い、Visual Studio Build Toolsの「C++によるデスクトップ開発」（MSVCとWindows SDK）も導入します。

UbuntuではRustのインストール前にCコンパイラーとリンカーも用意します。

```sh
sudo apt-get update
sudo apt-get install -y build-essential curl
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs -o /tmp/rustup-init.sh
sh /tmp/rustup-init.sh -y --profile minimal
. "$HOME/.cargo/env"
rustc --version
cargo --version
```

Node.js 24以上とnpmも必要です。`node --version` と `npm --version` で確認してください。Rustを導入した直後は端末を開き直すか、上記の `. "$HOME/.cargo/env"` でPATHを反映します。

すべてリポジトリ直下で実行します。初回は依存関係の取得とRustのコンパイルに数分かかります。

```sh
npm install
npm run build
npm start
```

[http://127.0.0.1:5173](http://127.0.0.1:5173) を開いてください。終了はCtrl+C。次回からは `npm start` だけで起動できます。外部AIサービスは不要です。

開発中も `npm run dev` で同じ5173番を使用します。画面とAPIをRustがまとめて配信し、Viteはファイル監視とビルドのみ行います。画面の変更は自動ビルド後にブラウザーを再読み込みすると反映されます。Rustコードの変更時はコマンドを再起動してください。通常起動との同時実行はポートが重複するため避けてください。

### 設定

`.env.example` の `APP_PORT` でポートを変更できます。既定はlocalhostの5173番です。AI生成とOllama連携は削除しました。

## 使い方

1. 検索・樹種フィルターから51件のプリセットを選びます。若木・老木・疎らな葉などの樹形を用意しています。
2. 「かたち」「質感」で枝、重力、葉や花を調整します。変更は自動反映されます。
3. タイムラインで成長を観察します。 再生は現在の世代から続き、最終世代にいる場合は種から再開します。再生中は次の世代を先読みし、バーも成長に合わせて連続的に進みます。停止すると進行中の1世代の伸長を終えて止まり、再開するとそこから続きます。 世代を変更すると、枝の断面と器官を補間して滑らかに伸縮します。補間中は実際に表示している世代も表示します。OSでアニメーションを減らす設定を使っている場合は即時に切り替わります。若い世代は細い幹から徐々に太くなります。再生は安全に生成できる世代で停止します。
4. 「ルール」で公理と置換規則を編集できます。エラー時は直前の樹木を残します。
5. マイライブラリへ保存、またはPNG / GLB / JSONで書き出します。

ドラッグで回転、右ドラッグで移動、スクロールでズーム。タッチは1本指で回転、2本指で移動・ズームです。

右側の「表示設定」にある「描画品質」で品質を選べます。低は1024pxの影と少ない光源で軽さを優先、中は2048pxの柔らかい影と補助光、高は4096pxの影と背面の補助光を使用します。高DPI画面の描画倍率上限も1 / 1.5 / 2に切り替わります。既定は中で、選択はブラウザーに保存します。「影・霧」と「グリッド」はオン／オフ表示付きの独立スイッチです。「アンチエイリアス」は輪郭を滑らかにする4x MSAAで、再読み込みせず切り替えられ、設定をブラウザーに保存します。

| ショートカット       | 操作             |
| -------------------- | ---------------- |
| F                    | 樹木全体を表示   |
| Space                | 成長の再生・停止 |
| Ctrl / ⌘ + Z         | 元に戻す         |
| Ctrl / ⌘ + Shift + Z | やり直し         |
| Ctrl / ⌘ + S         | 保存             |
| Ctrl / ⌘ + Enter     | 再生成           |

公理 `A`、規則 `A=F[+A][-A]` で二股の枝が繰り返されます。1行1規則、`#` で始まる行はコメント、`A=` は空置換です。

| 記号                 | 意味                        |
| -------------------- | --------------------------- |
| F / f                | 枝を描いて前進 / 描かず前進 |
| L / K / M            | 葉 / 花 / つぼみ            |
| + / -                | 左右に回転                  |
| & / ^                | 前後に傾ける                |
| / とバックスラッシュ | 枝の軸を中心に回転          |
| [ / ]                | 状態の保存 / 復元           |
| ! / ダブルクォート   | 太さ / 長さにscaleを掛ける  |
| 縦棒                 | 180度回転                   |

`F(2)`、`+(30)`、`!(0.7)` のように引数を指定できます。数値、四則演算、括弧、指数表記に対応します。プログラムコードは実行しません。従来の互換性のため、引数なしの `!` は `scale` を使用します。`widthDecay` はFで枝を伸ばす際の減衰です。

## 保存と書き出し

- 旧形式の `lsystem_presets_v1` は取り込みボタンで移行します。DBの作業中データが空なら、旧 `lsystem_studio_draft_v1` を読み込み、生成成功後にDBへ自動保存します。
- 保存先はRustサーバーのSQLiteです。ネイティブ版は `data/komorebi.sqlite3`（`DATABASE_PATH` で変更可）、Docker版は名前付きボリュームに保存します。作品ごとに自動保存し、同じ作品の更新が競合した場合は上書きを止めます。最新版を読み直すか、手元の編集を別作品として保存できます。読込失敗中は自動保存しません。
- 旧ブラウザー保存はマイライブラリの取り込みボタンでDBへコピーできます。同名の作品はスキップし、元データも保持します。JSONの読み込み・書き出しも利用できます。テーマ・描画品質など端末の表示設定のみブラウザーに保存します。
- ライブラリではサムネイル、作品名・樹種の検索、複製、名前変更、ごみ箱と削除取り消しを使えます。各更新を版として保持し、履歴から復元しても復元前の版が残ります。旧DBのライブラリと作業中データは起動時に作品へ移行します。
- ブラウザーには表示設定と最後に開いた作品のIDだけを記録します。自動保存は生成・再生と独立して実行し、通信待ちの編集は最新状態へまとめます。
- GLBには静止した樹木とテクスチャを含みます。枝は先細りを通常メッシュに焼き込み、葉・花・針葉も通常メッシュに焼き込みます。Blenderの「ファイル → インポート → glTF 2.0」で読み込めます。風、床、グリッドは含みません。
- PNGは現在の視点・背景を含みます。高さはモデル内の相対単位です。
- 実在する木の雰囲気を表現するモデリングツールで、生物学的な成長の厳密なシミュレーションではありません。

## 構成

```text
backend/                 Rust API・L-system・書き出しメッシュ
  src/engine.rs          展開、数式、3Dタートル、再現可能な乱数
  src/mesh.rs            表示用バイナリ、GLB用メッシュ
  tests/                 API、互換性、描画／書き出しの頂点一致
web/                     TypeScript UI、Three.js描画、保存と書き出し
  tests/reference/       比較検証専用の旧TS計算実装（配信されません）
shared/                  両側で使うプリセットと枝テンプレート
scripts/                 直下からの開発・検証・ベンチマーク
docs/                   設計・性能の記録
```

旧 `frontend/server` のNodeバックエンドは廃止し、Rustへ統合しました。配信用画像は `web/public/textures/` に集約しています。未参照の高解像度元画像6枚（69,127,918 bytes）は削除しました。独自L-systemで使う葉・花・汎用樹皮は維持しています。

## 検証

```sh
npm test
npm run typecheck
```

Nodeのみでフロントを検証する場合は `npm run test:web` / `npm run build:web` を使います。性能測定と設計は [docs/architecture.md](docs/architecture.md) を参照してください。

PowerShellの実行ポリシーでnpmが拒否された場合は `npm.cmd` を使用してください。

環境・影とグリッドはプレビュー左下で切り替えられます。影を受ける床の範囲はグリッドと一致します。木本の芽はシードに基づく個別の時期に伸長します。

## 全画面・テーマ・モバイル

キャンバスを画面全体に広げ、右の設定パネルと下のタイムラインを透過表示します。上部の「設定」でパネルを開閉できます。スマホでは初期状態で閉じ、風の設定も「表示設定」へまとめます。
「全画面」でブラウザーの全画面表示を切り替えます。非対応端末ではブラウザー内の表示を簡略化します。「表示設定」でライト・ダーク・自動（OSに追従）、FPS表示、影・グリッド・アンチエイリアスを切り替えます。
タイムラインの目盛り数字は非表示です。樹種別モデルは0.01世代刻みの形状生成に対応し、ドラッグを離すと選択位置の形状を生成します。自由な文字列L-systemは整数世代です。再生は既存の1世代先読みと連続補間を使用し、密なモデルの計算・描画時間によって待ちが生じる場合があります。

## 成長再生と自動品質

成長は小数位置で一時停止・再開できます。世代の数値入力と0.25〜4倍の速度変更に対応します（古典L-systemの生成指定は整数）。枝・葉・花・芽の安定したIDで世代間の形状を対応付け、位置だけの総当たり探索を避けます。

表示設定の描画品質「自動」はFPSの低下が続くと解像度・影を下げ、余裕が戻ると段階的に品質を回復します。視点操作中は一時的に品質を下げ、操作終了後に戻します。手動の低・中・高も選べます。

作品APIは `GET/POST /api/projects`、`GET/POST /api/projects/{id}`、`GET /api/projects/{id}/history` です。更新には `expectedRevision` が必要で、不一致は409です。削除は `deleted`、履歴復元は `restoreRevision` で行います。
